# MVS 抓拍后自动交给 FPGA 重构

自动入口：本文件夹的 `start.cmd`（或`启动自动处理.cmd`），打开图形界面后点击“开始监听”，详见同目录`自动界面操作说明.md`。手动选取已抓拍RAW的入口为`选择RAW重构.cmd`，具体步骤见`手动选图操作说明.md`。两种入口均使用已验证的speed3硬件，同一时间只运行一个处理任务，结果在电脑显示。

## 1. 接线

- 工业相机网线 → 电脑有线网口，使用 MVS 预览与抓拍；相机继续使用独立电源。
- 开发板 PS_UART → 电脑 USB；开发板通电。
- JTAG 下载器 → 电脑 USB 和开发板 JTAG。开发板重新上电后，启动程序会用现有 Vivado 批处理加载已经验证的 HYF1 bit，因此需要 JTAG。
- 本流程的结果直接回到电脑，不要求 HDMI/采集卡，也不要求相机网线接开发板。
- 关闭 MobaXterm 的开发板 COM 串口标签，让自动程序使用串口；MVS 可以保持打开。

## 2. 启动自动处理

双击 `F:\fpga\PenumbraSight_MVS_Snapshot_20261031\start.cmd`。

现在会打开图形界面；点击“开始监听”后，程序自动识别唯一的CH340串口并初始化。界面直接显示进度与结果；旧浏览器进度页也仍可手动访问：

http://127.0.0.1:8767/status.html

等待界面显示“正在监听：请在MVS点击一次抓图”。旧命令行入口另保留为`start_console.cmd`。

如果当前开机已初始化，会直接复用当前配置；重新上电时，启动程序先停止旧显示/DMA客户端、加载已匹配的驱动、通过 JTAG 加载已验证 bit，并进行原有的短初始化检查。这不是重新综合或布局布线。此时旧 HDMI 显示可能停止，本流程在电脑查看结果。

Vivado GUI、MATLAB GUI 和 OBS 不用手动打开；程序会调用已安装的 MATLAB 和必要的 Vivado 批处理。

若出现错误，点击界面“查看运行日志”，查看`watcher.log`；若界面本身无法打开，查看`auto_gui_errors.log`。不要在程序计算时手工重新下载bit、重启开发板或同时启动其他FPGA计算程序。

## 3. MVS 预览与抓一张

打开 `F:\MVS\MVS\Applications\Win64\MVS.exe`。

1. 在左侧“GigE → 以太网”选择 `MV-CS200-10GC(J77105203)`，连接设备。
2. 点击开始采集（三角形按钮），看到相机直接拍摄的实时墙面半影。
3. 固定场景与亮度，待画面稳定，点击**预览画面上方的小相机图标“抓图”**。它位于全屏图标右边、录像图标左边。
4. 只点击一次，等待保存。当前设置为“每1张抓取1张，抓取1张后停止”，无需先停止相机采集。

已经配置的“设置 → 录像/抓图”参数：

- 保存路径：`F:/fpga/PenumbraSight_MVS_Snapshot_20261031/captures`
- 自动存储：开启
- 图像格式：RAW
- 按数目抓图：每1张抓取1张，勾选“抓取”，数量1

如果换了 MVS 配置或保存路径，请按上述值恢复后点击“确认”。MVS 自动创建的相机型号子文件夹也会被监听。

相机的 **Pixel Format 必须是 BayerGB12（非 Packed）**，全幅 **5472×3648**。单张 RAW 应为 **39,923,712字节**。不能改为 BayerGB8、Mono 或压缩/打包格式。

## 4. 自动计算与返回

抓拍后不用手动复制文件、不用运行 MATLAB 命令：

MVS保存RAW → 程序等待写完并复制归档 → MATLAB解码、按固定标定采样 → 生成本张测量向量 → 发送开发板 → ARM初始化与调度＋FPGA矩阵/TV运算 → 自动下载结果 → 界面更新并由系统看图应用打开图片。

当前已启用speed3硬件版本。同一真实RAW的完整三通道板端实测：**29.0分钟→21.4分钟→11.4分钟**（最新682.815秒），本轮相对21.4分钟版耗时缩短约46.9%。另加RAW预处理和传输时间，不同照片可能变化。每通道仍1100次上限，全部3132值和完整迭代记录与旧版精确一致；本样本均未判定收敛，不能把达到上限当作收敛。提速不改变图像质量，也不是实时重构。

新bit：`F:\fpga\ps_speed3\vivado\board_hybrid\board_speed3.bit`；启动程序根据`config.json`加载它，不用手动打开Vivado，也不用每次重新布局布线。当前启动配置增加硬件版本和bit哈希核对；后续新任务的`result_report.json`也记录这两项。

计算期间可以继续看 MVS。新的抓拍会排队，每次只计算一张；请勿反复点击以免积压。

## 5. 去哪里看图

界面自动更新；计算完成会在右侧显示并自动打开本次`reconstruction.png`，也可点击“打开最终重构图”。

每次独立保存于：

`F:\fpga\PenumbraSight_MVS_Snapshot_20261031\jobs\日期时间_任务号\`

- `capture.raw`：本次原始抓拍，保留不覆盖。
- `raw_preview.png`：相机原图预览，仅显示提亮。
- `wall_preview.png`：实际送入计算的墙面采样区预览。
- **`reconstruction.png`：自动反馈的重构显示图。**
- `reconstruction_native.png`：29×36原生网格显示图。
- `reconstruction.npy`：有符号数值结果，不经显示截断或归一化。
- `reconstruction_world_x_right.png`：另存的世界坐标方向视图。
- `result_report.json`：FPGA结果哈希、用时、各通道迭代次数及收敛状态。
- `measurement.mat`：本次采样、固定配置及预处理数据。
- `matlab.log`：该任务的电脑预处理日志。

网页中的相机墙面预览与最终重构是两种图。MVS 的实时画面始终是相机测量预览，不是 FPGA 复原结果。

## 6. 停止、恢复与常见问题

- 点击“停止监听（完成当前张）”，本张完成后后台退出，排队任务保留。仅关闭界面不会停止后台监听；停止监听不会关闭相机。旧命令版仍可在窗口按Ctrl+C。
- 新增“停止并重置”可中止当前任务、取消待处理队列，不删除RAW和已完成结果；两个界面都可用。具体行为和检查范围见`停止重置操作说明.md`。
- 若电脑程序意外关闭而板子仍计算，重新打开 `start.cmd` 会继续轮询已有任务，避免重复提交。
- 若板子中途断电，当前任务会报失败；恢复初始化后需要重新抓拍。本程序不偷偷重跑失败任务。
- 串口打不开：关闭 MobaXterm 的 COM 标签，确认 PS_UART 数据线接电脑。只有一个 CH340 时自动选端口；多个 CH340 时在 `config.json` 把 `port` 改成正确的 `COM11` 等名称。
- JTAG初始化失败：确认下载器连接与板子通电，查看 `initialization/vivado_program.log`。当前脚本沿用已验证的下载器标识，换下载器时需核对该标识，不能随便选错目标。
- RAW大小/格式不符：在MVS恢复上述全幅BayerGB12设置，再抓拍。
- 已保存但看图应用未打开：直接看界面右侧，或点击“打开最终重构图”，也可在对应任务文件夹双击`reconstruction.png`。
- 如需左右翻转最终显示，在 `config.json` 设置 `flip_horizontal` 为 `true` 后重启程序；原始数值和另存方向图均保留。
